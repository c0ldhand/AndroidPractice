# Практика 6 — Профиль

Ветка `Practice6` создана от `Practice5`. Каталог, фильтры и избранное сохранены.

## Реализация

- Вкладка «Профиль»: аватарка, ФИО, должность, кнопка «Резюме», карандаш в верхней панели.
- Экран «Редактирование»: фото, ФИО, прямая ссылка на документ, необязательная должность, кнопка «Готово».
- При входе запрашивается системное разрешение на доступ к фотографиям. При отказе экран закрывается.
- По нажатию на аватарку открывается выбор «Галерея / Камера». Галерея приложения читает доступные фотографии из MediaStore; исходники не изменяются.
- Камера запускается через `ActivityResultContracts.TakePicture`; разрешение камеры запрашивается при выборе этого источника. Отмена и отказ сохраняют предыдущую аватарку.
- «Готово» дожидается записи на диск, возвращает в профиль и обновляет его через `StateFlow`.
- Возврат без сохранения отменяет черновик. Черновик и URI незавершённой съёмки хранятся в `SavedStateHandle` для восстановления экрана.
- Кнопка «Резюме» скачивает документ по прямой HTTPS-ссылке и открывает через `ACTION_VIEW` с MIME-типом и временным доступом на чтение.
- Ссылка без схемы, например `example.com/cv.pdf`, нормализуется в HTTPS. Пустая ссылка допустима; кнопка резюме тогда отключена.
- Ошибки сети, HTTP, HTML вместо файла, пустой ответ и документы больше 25 МБ обрабатываются в интерфейсе. Незавершённые загрузки удаляются.

## Хранение и архитектура

Для одного небольшого профиля выбран JSON-файл `filesDir/profile.json`: простая структура, без таблиц, поиска и связей, поэтому база данных здесь не требуется. `AtomicFile` сохраняет предыдущую версию при незавершённой записи; чтение и запись выполняются на `Dispatchers.IO` под `Mutex`.

В JSON записываются ФИО, URI аватарки, URL резюме и должность. Фото копируется в `filesDir/avatars/`, уменьшается до 1024 пикселей и сохраняется как JPEG с учётом ориентации EXIF. Сохранённая аватарка не зависит от разрешений галереи или удаления оригинала. Временные снимки находятся в `filesDir/camera/`, резюме — в `filesDir/resumes/`. Эти два каталога исключены из резервного копирования; профиль и аватарки сохраняются вместе.

`FileProvider` открывает только три названных каталога, а не всё хранилище приложения. URI камеры передаётся системному приложению камеры, URI документа — выбранному просмотрщику.

```text
ui/screens/profile                ProfileRoute, ProfileEditRoute, отображение и системные контракты
viewmodel                         ProfileViewModel, ProfileEditViewModel, состояния и события
domain/model                      UserProfile, ResumeDocument
domain/usecase                    SaveProfileUseCase, проверка и нормализация ссылки
domain/repository                 ProfileRepository, ProfileMediaRepository, ResumeRepository
data/local                        JSON, MediaStore, копирование фото и файлы камеры
data                              DownloadedResumeRepository, скачивание на IO
platform/images                   декодирование и ориентация изображения
di/AppContainer                   зависимости и фабрика ViewModel
```

Для каждого нового экрана создаётся собственная ViewModel в его Route с областью жизни записи навигации. Навигация передаёт только события перехода; доменный слой не зависит от Android.

## Разрешения

| Версии Android | Доступ к галерее |
| --- | --- |
| Android 7–12L / API 24–32 | `READ_EXTERNAL_STORAGE` |
| Android 13 / API 33 | `READ_MEDIA_IMAGES` |
| Android 14+ / API 34+ | `READ_MEDIA_IMAGES` и `READ_MEDIA_VISUAL_USER_SELECTED`: полный или частичный доступ |

На Android 14+ галерея показывает только доступные приложению фото; кнопка «Изменить доступ к фото» снова открывает системный выбор. Доступ проверяется перед каждым открытием галереи. `CAMERA` проверяется перед каждой съёмкой. Разрешения на запись внешнего хранилища и управление всеми файлами не используются.

Явный запрос доступа при входе и собственная галерея выбраны для выполнения сценария практики. Для приложения, которому нужен только один снимок, системный Photo Picker позволил бы обойтись без широкого разрешения: [документация Android](https://developer.android.com/about/versions/14/changes/partial-photo-video-access).

## Проверка

Проверено 27.10.2026:

- Debug- и release-сборки — успешно.
- 33 unit-теста — успешно, включая 8 тестов новой логики профиля.
- Android 10 / API 29 — все 19 инструментальных тестов прошли.
- API 37, Pixel 8 — все 19 инструментальных тестов прошли.
- Отдельный запуск демонстрационного сценария на API 29 — 2 теста прошли, скачанный PDF действительно открыт в системном внешнем просмотрщике.
- Lint — 0 ошибок. Предупреждения о версиях зависимостей, неиспользуемых ресурсах, платформенном ExifInterface и оформлении манифеста не блокируют сборку.

API 24–28 и API 33 отдельно на устройстве не запускались. Поддержка частичного доступа на API 34+ реализована; в полном сценарии на API 37 проверялись отказ и полный доступ.

```powershell
.\gradlew.bat :app:assembleDebug :app:assembleRelease :app:testDebugUnitTest :app:assembleDebugAndroidTest :app:lintDebug --max-workers=2
.\gradlew.bat :app:connectedDebugAndroidTest --max-workers=2
```

Для проверки системных диалогов `ProfileFlowTest` запускается на чистой установке приложения. Первый тест отказывает в доступе, второй разрешает доступ, выбирает фото, делает снимок камерой, вводит данные, сохраняет и восстанавливает Activity. `ProfileStorageTest` проверяет JSON, Unicode, повреждённый файл, независимость аватарки от оригинала, удаление временного снимка и скачивание через локальный HTTPS-сервер, включая ошибки и очистку файлов.
